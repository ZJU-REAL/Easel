# 需求信号采集（社媒蓝海选题）

蓝海选题的需求信号**不来自搜索引擎月搜索量**，而来自中文社媒的三个真实需求现场：**平台搜索联想词、平台热搜、评论区未满足需求**。本文件讲每类信号怎么采、怎么读。三类信号交叉验证，单一信号不足以判定需求。

## 一、平台搜索联想词（长尾需求）

用户在平台搜索框输入的词，就是最直接的需求表达。

- 用 `web_search` 搜 `{赛道}` 配合意图词：`怎么 / 如何 / 推荐 / 避坑 / 对比 / 教程 / 值不值`，观察"相关搜索"里冒出的长尾词
- 加平台定向：`{赛道} site:xiaohongshu.com`、`{赛道} site:bilibili.com`，看平台内的联想与相关笔记
- 按意图归类：**学习型**（怎么做）、**决策型**（选哪个/值不值）、**问题解决型**（XX 怎么办）、**种草型**（推荐/好物）

**读法**：联想词越具体、越口语化，需求越真实（"小户型玄关没有鞋柜怎么办" > "玄关设计"）。长尾具体词往往就是蓝海入口。

## 二、平台热搜（时效需求）

热搜提供**时效性选题窗口**。采集统一走 [../../shared/hotlist-apis.md](../../shared/hotlist-apis.md)（60s API，微博/抖音/知乎/头条/小红书/百度热榜），本文件不复制端点。

- 从热榜筛出与赛道相关的话题，记录热度值作为时效候选池
- 判断借势窗口：热点是刚起（可抢先）还是已过顶（红海）
- **只跟契合赛道的热点**，硬蹭不可持续（见 SKILL 主体原则）

## 三、评论区未满足需求（最高质量信号）

评论区是需求信号密度最高的地方——用户主动说出"现有内容没满足我什么"。

- `web_search` 找赛道热门内容 → `web_fetch` 抓内容页读评论区（反爬时降级见下）
- 重点抓四类信号：
  - **追问型**高赞评论："求出个 XX 教程""能不能讲讲 XX" → 明确未满足需求
  - **吐槽型**："说了等于没说""没讲到重点" → 现有内容的质量洼地，可做更好
  - **提问点赞数**：点赞越高 = 需求越普遍
  - **收藏/转发 >> 点赞**的内容：实用但表达不到位，有改进空间

**读法**：一条追问被大量点赞 = 已验证的需求，优先级高于任何搜索联想词。

## 采集降级方案

平台内容页 / 主页反爬（小红书、抖音、B站尤甚）时逐级降级：

1. `web_fetch` 内容页直取评论 → 失败则
2. `web_search` 取搜索结果摘要里的评论片段与讨论 → 失败则
3. 用公开报道、第三方聚合里的用户反馈间接推断，并标注"来源：公开搜索，非直取"

绝不因为抓不到就编造需求信号——宁可标注"信号不足，待验证"放进观察池。
