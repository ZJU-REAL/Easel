# 场景卡 Schema（写复杂章节前的分解工具）

> 借鉴 GOAT-Storytelling-Agent：**用层级分解替代长上下文**。写一章前先把它拆成若干场景卡，
> 每卡是一个 scope 良好的最小叙事单元。锚定全局 bible，只需上一场景的出口就能续写，
> 避免把全书塞进上下文导致漂移。简单章节可跳过，直接写正文。

## 单张场景卡字段

| 字段 | 说明 |
|------|------|
| **场景号** | 本章内序号（1,2,3…） |
| **地点/时间** | 在哪、何时（与 canon 时间线一致） |
| **在场角色** | 谁在场（状态引用 state/character-state.md） |
| **目标** | 本场景主角想达成什么 |
| **冲突/阻碍** | 谁/什么在挡路（无冲突的场景多半可删或合并） |
| **story value 涨落** | 本场景开始与结束时，主角处境的价值变化（如 安全→危险 / 弱→强 / 被疑→被信）。每个场景都应有价值翻转，否则平淡 |
| **情绪基调** | 紧张/温情/压抑/爽快…（引导用词与节奏） |
| **出口/钩子** | 场景结束时留下的悬念或新问题，接下一场景或本章末钩子 |
| **伏笔操作** | 本场景埋下或回收了哪个伏笔（同步登记 bible/canon.md） |

## 使用流程

1. 读本章的章纲（`outline/chapters.md` 对应行）+ 相关 bible/state 切片。
2. 把本章拆成 2–5 张场景卡（一章通常一个主场景 + 若干过渡）。
3. **检查价值翻转**：每张卡 story value 首尾必须不同；连续几张卡方向单一（全在变强/全在受苦）要调整节奏。
4. 逐场景写正文，每场景锚定 bible、承接上一场景出口。
5. 本章末落一个强钩子（见 web-novel-methodology 钩子库）。

## story value 常见维度（挑 1–2 个作为本场景的翻转轴）

- 安全 ↔ 危险
- 强 ↔ 弱（实力/地位）
- 被信任 ↔ 被怀疑
- 希望 ↔ 绝望
- 亲近 ↔ 疏远（关系）
- 已知 ↔ 未知（信息）

> 一部好看的连载，是这些价值轴持续、有节奏地来回翻转的过程——别让主角长期停在同一个值上。
