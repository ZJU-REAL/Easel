# 故事引擎（story engine）——治「剧情简单 / 人物扁平」的根

> 剧情烂的根因不是"题材选错"，而是**没有引擎**：事件是"然后…然后…"堆的、人物是被作者推着走的、反转是空降的。
> 本文给一套**因果驱动 + 人物能动**的故事引擎。**写 series-bible 前必读**；每个主要角色必须建"行动模型"。
> 方法论借鉴 worldwonderer/drama-skills（story-craft）。

## 一、戏剧承诺（先回答五问，再写任何剧情）

一部剧开机前先答清楚，答不清 = 只有题材标签、没有戏：

1. **主体**——谁在承受压力、做被观众跟随的选择？
2. **追求**——他此刻要得到/守住/揭开/逃离什么？
3. **昂贵阻力**——谁/什么让这个追求持续付代价？（必须**有筹码、能真挡**，不是纯使坏）
4. **独特矛盾**——为什么他"最有效的策略"恰恰会伤害他所珍视的东西？（人物弧光的来源）
5. **反复回报**——观众每集期待兑现的是哪种变化（爽/虐/甜/悬）？

**压成一句可测的承诺**：

> 当【主角】用【惯常策略】追求【当前目标】时，【对抗机制】迫使其付出【核心代价】；
> 系列反复兑现【观众回报】，直到【终止性转变】发生。

**承诺自检（命中任一 = 概念太弱，重写）**：
- 换掉人名/职业后，这句话和别的剧没区别 → 独特矛盾不具体。
- 一句话解释就能让反派收手 → 阻力没有结构性、没筹码。
- 主角不行动、结果也会到 → 主角没有戏剧能动性。
- 只有大结局才回报 → 每集没有回报，中段必空。
- 每集回报形式都一样 → 没有变化空间，观众腻。

## 二、冲突循环（一集/一段的最小引擎）

```
触发压力 → 主角依信念选策略 → 对手/制度/关系做出「有能力的」反制
→ 主角拿到局部结果 + 承担新代价 → 某个状态改变
→ 新状态制造下一轮「更难的」选择
```

**状态维度**（每次升级至少改一个、并说清改了哪个）：权力 / 知识 / 关系 / 暴露 / 资源 / 物理状态 / 道德成本。
**引擎测试**：把台本里的「选择」和「代价」删掉，剧情还照样成立 → 说明是作者在推、不是人物在走，重写。

## 三、人物行动模型（每个主要角色必建，替代"年龄+外貌+性格"）

只写年龄/外貌/性格 → 预测不了任何选择、人物必扁平。给每个主要角色写**能预测选择**的 8 字段：

| 字段 | 说明 |
|---|---|
| **表层目标** | 他现在想让什么发生 |
| **保护对象** | 就算失败也不肯丢的东西/人 |
| **自我解释** | 他如何为自己的行为找正当性 |
| **惯常策略** | 控制/讨好/试探/退避/揭穿/交易/豪赌…（选 1–2 种主导） |
| **筹码** | 他能给出或拿走什么（有筹码才推得动戏） |
| **盲区** | 他持续误读的东西（反转/打脸的燃料） |
| **底线与越线条件** | 什么情况下他会突破底线 |
| **可变事实** | 哪个"知识/关系"一旦变化，他的策略就会变（编剧的开关） |

## 四、观众为什么站他这边（可跟随性 · 最被 AI 忽略的一块）

8 字段让角色"可分析"，但不"可跟随"——结构对、却没人想看。**ep1 内至少可见地回答其一**：

- **他在承受什么不该由他承受的？** 不公必须**具体可见**（被冒名领功、排班被偷改），不是"他是个好人"。
- **他在替谁扛？** 替一个 **ep1 就出场的具体人** 扛 > 替自己扛（后者像固执）。
- **他要的东西，观众自己是不是也想要？** 尊严/被认可/把一件事做完/护住一个人 > 抽象的"复仇"。
- **他有什么本事是观众想借来用一次的？** 看穿谎言/修好没人能修的/在羞辱里保持体面——决定"同情他"还是"想成为他"。

⚠️ 这不是"写讨喜"。可跟随来自**「他想要而尚未得到」**，不来自可爱。永远正确/永远被善待/立刻就赢，会同时抵消不公与渴望。

## 五、关系 = 双向压力（不要只写标签）

别只写"母女 / 上司下属 / 旧恋人"。每对关键关系写**两个方向**：

```
A 需要 B 提供什么 / 害怕 B 看见什么 / 用什么约束 B
B 需要 A 提供什么 / 害怕 A 拿走什么 / 用什么反制 A
```

场景冲突来自**这些力此刻无法同时被满足**。每个关键角色都要有独立目标 + 可用筹码，不是"只负责递线索/给主角制造麻烦"的工具人。

## 六、爆款 vs 流水账（自检对照）

| 维度 | 爆款（working） | 流水账（flat） |
|---|---|---|
| 阻力 | 反派有**筹码**、能真挡 | 反派只会不断升级恶意 |
| 因果 | 事件用「因为/所以」串、不可乱序 | 「然后…然后…」、可随意换序 |
| 主角 | 主动选择并付代价 | 等着被救、靠巧合 |
| 升级 | 改变**状态**（权力/知识/关系/暴露/资源/道德） | "更生气、更吵、更危险"但没有新能力/知识/代价 |
| 铺垫 | 铺垫会**改变后续选择** | 铺垫只是拖延解释 |
| 关系 | 双向需求与约束 | 只有标签 |

> **升级正例**：她删掉一条调换记录去护新供应商 → 被挤掉的老供应商拿订单证据当众发难 → 问题从"怎么排班"升级成"谁有权改记录"。（改变了状态与意义，不是"吵得更凶"。）

## 七、如何用

1. 开机先写**戏剧承诺**并过自检；不过就别往下写。
2. 每个主要角色建**行动模型 + 可跟随四问答案**，写进 series-bible（见 `series-bible-schema.md`）。
3. 写每一集/每一段用**冲突循环**推进，升级必须命名"改了哪个状态"。
4. 反转按 `genre-hooks-handbook.md` 的**因果反转一句话测试**生成。
5. 写完过 `drama-review-rubric.md` 的 A/B 门（故事引擎门 + 人物可跟随门）。
