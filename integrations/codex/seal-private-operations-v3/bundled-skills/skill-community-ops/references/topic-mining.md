# 评论区选题反哺

> 供 skill-community-ops 模式 B 使用。把评论区当选题金矿，从真实评论里聚类出诉求，转成下一步选题。

## 一、评论聚类维度

通读评论，按下列维度归类，并标注信号强度（高频 / 中频 / 零星但尖锐）：

1. **高频疑问** — 反复被问的同一个问题（"XX 怎么选"、"新手怎么开始"）。信号最强，往往是最好的选题。
2. **重复诉求 / 许愿** — "求出 XX 教程"、"能不能测测 XX"、"什么时候讲 XX"。用户直接点单。
3. **争议点 / 分歧** — 评论区吵起来、观点两极的话题。天然带互动和传播。
4. **吐槽 / 痛点** — 对某产品、某现象、某流程的集中抱怨。痛点即内容需求。
5. **延伸好奇** — "那 XX 呢"、"进阶怎么办"、"反过来会怎样"。现有内容的自然续集。
6. **误解 / 认知偏差** — 评论里暴露的普遍误区。适合做"辟谣/纠错/避坑"类高传播选题。

## 二、评论转选题公式

把高价值聚类转成 3-5 条具体选题，每条按下列结构产出：

- **选题方向**：一句话说清做什么（可给 1-2 个标题方向）。
- **来源**：来自哪条/哪类评论（引用或概括原评论）。
- **为什么值得做**：信号强度 + 为什么这个选题能接住需求 / 有传播潜力。
- **建议形式**：图文 / 短视频 / 合集 / 问答 / 对比，按平台和选题性质定。

选题优先级排序参考：
- 高频疑问 > 重复许愿 > 争议点 > 痛点吐槽 > 延伸好奇 > 误解纠错（但争议点和误解纠错的传播上限更高，可视账号目标提权）。
- 一个高频疑问可拆成"入门版 + 进阶版"两条，形成系列。
- 争议点选题注意立场：给多方视角或明确亮出观点，别骑墙。

## 三、注意

- 只从**真实评论信号**出发，不硬凑；评论量太少时如实说明"信号不足，建议积累更多评论再挖"。
- 区分"个别声音"和"普遍需求"，零星但尖锐的评论可做但要标注风险（可能只是少数人诉求）。
- 挖出的选题可回写到内容日历 / 选题池，与 skill-strategy-advisor、skill-content-calendar 联动。
