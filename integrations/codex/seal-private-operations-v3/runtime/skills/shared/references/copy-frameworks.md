# 文案框架库（公共源）

> Easel 经典文案框架的**唯一定义源**（copywriting / post-formatter 共用），避免各处重复定义漂移。
> 本文件只给**框架定义 + 选择规则**；各 SKILL 的应用层（copywriting 的文案类型结构模板、post-formatter 的帖子行数分配）留在各自 references 里。
> 引用方式（CWD=项目根）：`skills/shared/references/copy-frameworks.md`。

选一个框架 = 一条内容主线；把主题拆进它的各阶段，按顺序写。框架决定"信息怎么排布"，不决定"字怎么写"。**选定后只用一个，不混用。**

---

## PAS（痛点-方案）｜痛点 → 放大 → 方案
- **Problem 痛点**：一句话点破读者正在经历的具体困扰，越具体越有代入感
- **Agitate 放大**：不解决会怎样（成本、尴尬、持续困扰），让人坐不住
- **Solution 方案**：给出解法，落到可感知的结果
- 适用：带货、种草、卖服务、详情页——任何"读者有明确痛点"的场景。

## AIDA｜注意 → 兴趣 → 欲望 → 行动
- **Attention 注意**：钩子抓眼球（痛点/反差/利益/提问）
- **Interest 兴趣**：放大相关性，让用户觉得"说的就是我"
- **Desire 欲望**：卖点 + 证据 + 场景，制造想要
- **Action 行动**：明确 CTA + 行动理由（限时/赠品/价格锚点）
- 适用：信息流广告、落地页、新品发布、活动预热等完整转化链路。

## BAB｜现状 → 改变后 → 桥梁
- **Before 现状**：用户当前的糟糕/停滞状态
- **After 改变后**：用了之后的理想状态
- **Bridge 桥梁**：产品就是从现状到理想的那座桥
- 适用：前后对比强烈的转变类（减肥/学习/效率）、种草、转化。

## FAB（卖点提炼核心）｜特性 → 优势 → 利益
- **Feature 特性**：产品客观拥有什么（成分、参数、功能、材质）
- **Advantage 优势**：这个特性带来什么好处（比别的强在哪）
- **Benefit 利益**：对用户意味着什么（能解决什么、变成什么样）
- 写法：`因为{特性}，所以{优势}，这意味着你能{利益}`。主推"利益"，用"特性"做证据。
- 适用：卖点提炼、详情页卖点分层。

## 4U（强钩子标题原则）｜有用 / 紧迫 / 独特 / 具体
- **Useful 有用** / **Urgent 紧迫** / **Unique 独特** / **Ultra-specific 具体**
- 用于标题/信息流首行自检，四条尽量多占。

## STAR｜情境 → 任务 → 行动 → 结果
- **Situation 情境**：谁在什么处境
- **Task 任务**：当时要解决的具体问题或目标
- **Action 行动**：一步步做了什么（可用 1. 2. 3.）
- **Result 结果**：可量化的成果或转变
- 适用：案例复盘、经验分享、客户故事、方法论拆解。

## SLAY｜故事 → 道理 → 建议 → 你
- **Story 故事**：一段真实、有画面的小故事开场
- **Lesson 道理**：从故事里提炼出一个观点
- **Advice 建议**：给读者可落地的具体做法
- **You 交给你**：把话题抛回读者，引导互动
- 适用：个人向、干货带情绪、观点输出、求共鸣与评论。

---

## 框架选择规则（无指定框架时按内容目的判断）
- 读者有明确痛点、要转化 → **PAS**
- 要从"围观"引到"心动"、做推广 → **AIDA**
- 前后状态对比强烈、讲转变 → **BAB**
- 逐条提炼卖点 → **FAB**；标题自检 → **4U**
- 有案例/数据、讲怎么做到的 → **STAR**
- 想讲故事、输出观点、求共鸣互动 → **SLAY**

判断依据是内容目的，不是平台。
