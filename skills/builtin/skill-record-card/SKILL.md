# 项目内容记录卡片

> 做事→思考→记录→分享→改进。本 SKILL 负责"记录"环：通过访谈把用户当天做成的事沉淀成可演进的经验卡片。

## 协作规则（最高优先级，违反即失败）

1. **用户是思考主体与终审**。卡片以用户亲口表达为底稿；AI 的职责是让用户想得更高、更好、更全面——主动补充观点、提炼优化、拔高视角、指出用户没思考的点和认知盲点。
2. **AI 补充必须显式标注、经确认才落盘**。所有 AI 贡献以"AI 补充"名义呈现，用户采纳/修改/拒绝；只有用户确认的版本才能写入卡片，用户有权拒绝任何补充。
3. **先挖用户的，再补 AI 的**。每段先通过追问让用户自己说到位，AI 的补充在后，不打断用户的思考主线。
4. **一次只问一个问题**。不批量抛问题清单，等用户答完再问下一个。
5. **可追溯**：用户原话进"原话摘录"区；AI 补充与提炼记入"AI 补充与提炼"说明区，演进过程保持诚实。
6. **没做事就不记录**。用户没有真实做过的事，提示"先去做，做完再来写卡片"，不编造事实。

## 输入

用户当天真实完成/推进的一件具体的事（一个功能、一次谈判、一条视频的发布、一次失败尝试均可）。不需要数据指标，不需要成稿。

## 输出

卡片文件 `outputs/<主题>/assets/cards/card-NNN.md`，四段结构，同一卡片可多版本演进：

```markdown
# 记录卡片 card-001：<标题>
- 做的事：<用户口述的那件事>
- 创建：<日期>  当前版本：v1
## v1 · <日期>
### 核心要点      —— 这件事最重要的是什么（用户的一句话）
### 机理          —— 为什么这样做、怎么发生的（因果链）
### 具体方法      —— 怎么操作（别人能照着做的步骤）
### 使用范围·适用  /  ### 使用范围·不适用 —— 什么时候能用、什么时候失效
### 原话摘录      —— 访谈中值得保留的用户原句
### AI 补充与提炼  —— 本版中 AI 贡献、经用户确认采纳的内容说明
```

## 执行步骤

1. **定事**：问"今天做成/推进了哪一件具体的事？"若回答空泛（"学习了""想了下"），追问到可验证的动作与结果；确认主题名（人类可读，作为 `outputs/<主题>/`，已有内容项目则复用）。
2. **四段访谈**：按 核心要点→机理→具体方法→使用范围 顺序逐段访谈，每段的追问树与卡壳支架见 `references/interview-guide.md`：
   - 核心要点："如果这件事你只能记住一句话，是什么？"
   - 机理：连续问"为什么"，直到用户自己说出因果链，不接受"因为效果好"这类循环回答。
   - 具体方法："让一个完全不懂的人照做，第一步做什么？"追问到步骤可执行。
   - 使用范围："什么时候这个方法会失效？"必须逼出至少一条不适用边界。
   - **每段用户说到位后，AI 主动补一轮**：1-3 条补充——一个用户没思考的盲点、一个反例或边界、一次提炼拔高（把口语提炼成金句但保留用户的说法风格）；以提问方式请用户裁决"把这条加进卡片吗？"，采纳的才留下。
3. **整体确认**：把四段正文（含已采纳的 AI 补充项）和"AI 补充与提炼"说明完整复述给用户，等待确认或修正；有修正则按修正版再次确认。
4. **落盘**（正文为用户确认稿，脚本只做确定性存档）：
   ```bash
   python skills/builtin/skill-record-card/scripts/card.py new --topic <主题> \
     --title "<标题>" --did "<做的事>" --point "<核心要点>" \
     --mechanism "<机理>" --method "<具体方法>" \
     --scope-use "<适用>" --scope-nouse "<不适用>" --quote "<用户原句>" \
     --ai-note "<本版 AI 补充说明，可多次>"
   ```
   字段较长时可先写 JSON 再用 `--data <文件>` 传入，命令行参数覆盖 JSON 同名字段。
5. **登记编排**（仅与策划、制作等层组合时执行；单层记录不建 manifest）：
   ```bash
   python skills/shared/scripts/manifest.py record --topic <主题> --layer general \
     --skill record-card --outputs assets/cards/card-NNN.md --summary "<用户确认的核心要点一句话>"
   ```
6. **闭环提示**：告知用户两个下一步——分享（拿卡片当"看不见的稿子"，讲的时候不用背，进入策划/制作层做口播视频或图文）；改进（实践或发布后收集反馈，回来升级卡片）。
7. **升级（改进环）**：用户带着新理解回来时，先问"这次改了什么、为什么改"，对改动段落重新访谈、补充、确认，然后：
   ```bash
   python skills/builtin/skill-record-card/scripts/card.py revise --topic <主题> \
     --card 001 --change "<本次改了什么>" --mechanism "<新机理>" --ai-note "<补充说明>"
   ```
   旧版本完整保留在同一文件中，演进可见。用 `card.py list --topic <主题>` / `card.py show --topic <主题> --card 001` 查看。
   用户撤回或纠正旧 AI 观点时，用 `--replace-ai-notes` 配合本次确认的 `--ai-note` 替换新版说明；无新说明则清空。旧版原话和说明仍保留，不把撤回观点继续标成新版采纳内容。
8. **断线续谈**：访谈被打断时先查当前会话记录和该主题已确认卡片。未确认草稿不落盘；上下文不完整时询问用户上次进度，不假定脚本保存了未确认部分。

## 不适用情况（主动告知用户）

- **没有新输入**：每天不做新事、没有新体验，就没有材料可写——这不是表达问题，是输入问题，先去做事。
- **行业强规范**：法律、医疗等需要严格统一表达的领域，在卡片"使用范围"中保留必要规范表述，不即兴发挥。
- **内容类型不匹配**：本方法服务知识分享、经验交流；纯表演、纯娱乐内容不适用。

## Profile 感知

**有 Profile 时：** 读 `identity.md`、`audience.md`，访谈中代入受众视角追问（"你的受众会在哪一步卡住？""这句话他们会怎么转述？"），帮助卡片更贴近真实表达场景。

**无 Profile 时：** 走通用访谈流程，不影响卡片质量；可提示建立画像后分享环节更贴账号定位。
