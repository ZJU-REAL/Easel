# 可重做的本地步骤检查点

`skills/shared/scripts/artifact_checkpoints.py` 为本地产物计算提供独立检查点，
短视频合成器通过 `assemble --resume` 接入逐镜头渲染。它与对话任务账本分开提交和使用，
不修改 Agent 底座，不依赖 Web 服务，也不推断远端任务结果。

## 复用条件

调用方验证输出目录后，以 `ArtifactCheckpoints(directory)` 持有整个工作流的独占文件锁。
`run(key, input_fingerprint, produce)` 只适用于可安全重做的本地计算：

1. 输入指纹包含全部渲染参数、渲染器版本和输入文件内容摘要。
2. 只有已提交记录、指纹相同、产物存在且内容摘要匹配时才跳过执行。
3. 新步骤写入独有的暂存文件；返回后再次检查输入指纹，输入改变则不提交。
4. 产物同步写入磁盘后，原子替换检查点清单。未提交的暂存文件不被当作完成。

合成器让指纹核验与渲染使用同一个解析后的源文件路径，避免符号链接切换造成错配。
新镜头提交前还会核验视频流、尺寸和预期时长（30fps 下允许约两帧误差），并完整
解码验证；损坏或被截短的镜头不能提交成功记录，也不能替换已有成片。

步骤返回 `(artifact_path, reused)`。调用方不得改写已返回的检查点产物；
生成器必须在返回前关闭所有写入者，不得留下后台进程继续改写该文件。
`atomic_output(destination)` 可以在最终输出完成前保留上一份成品。

## 故障边界

- 执行失败、空产物或输入变化不会提交完成记录；旧记录和成品保留。
- 进程退出由操作系统释放锁。另一个进程持锁时直接报错，不等待或抢占。
- 未知清单版本或损坏清单报错，不静默重建。缺失或被修改的产物需要重新计算。
- 强制结束可能留下无记录的产物或暂存文件。它们不会被复用，也不会自动删除。
  仅在确认所有工作进程和渲染子进程退出后，才可人工清理整个检查点目录。
- 只验证本机文件系统上的进程中断恢复；不承诺网络文件系统或断电后的持久化结果。
  每次复用仍会核验文件内容，不能用文件名、大小或修改时间代替摘要。

未提交步骤可以再次执行，因此本机制不适用于付费 API、发布、发送消息等外部动作，
也不提供任意工具“恰好执行一次”的保证。那些步骤需要结果查询或幂等协议后才能接入。

## 真实合成验收

`tests/test_assemble_resume_ffmpeg.py` 通过合成器 CLI 调用真实 FFmpeg，使用本地生成的
两张小图片，不调用模型或平台 API。测试第二张素材损坏时失败、保留旧成片及第一个
已提交镜头；修复素材后重新运行，只复用第一个镜头，最终用 ffprobe 校验成片时长。
再次执行会复用两个镜头。单元测试另外覆盖渲染参数改变、字幕变化、产物损坏与竞争写入。
另外使用后段编码包损坏的视频验证失败保留旧成片、拒绝短镜头缓存，以及修复后正常成片。

`Video checkpoint acceptance` 工作流显式安装并检查 FFmpeg/ffprobe 后运行这些测试，
避免因为缺少渲染器而把真实媒体验收静默跳过。本地无渲染器时该测试会标为 skipped，
这种结果不能当作媒体验收通过。
