# 持久化工具调用预留

`agents/tool-budget/durable-store.mjs` 提供基于 Node.js 内置 SQLite 的调用额度账本，
供执行前准入集成使用。本模块本身不安装插件、不执行工具、不取消模型，也不自动恢复任务。
运行环境使用 Node 24；不新增第三方数据库依赖。

`new DurableToolStore(absolutePath, {create: true})` 仅用于首次显式初始化：父目录必须已存在，
数据库文件必须不存在。运行时使用不带 `create` 的构造方法，丢失、损坏或未知版本的数据库
直接拒绝打开，不能自动建新库重置额度。文件创建请求仅属主读写权限；Windows 仍需正确配置
父目录 ACL。数据库只存任务及调用标识的哈希、预算和时间，不存消息、工具参数或凭据。

调用者先以 `{agentId, sessionKey, runId}` 和 `{maxCalls, timeoutMs}` 调用 `begin`，随后在
每个工具执行前调用 `reserve(identity, callId)`，只有返回 `allowed: true` 才可执行。
SQLite `BEGIN IMMEDIATE` 事务将调用标识和额度扣减一并提交；失败、取消或后续策略拒绝均不退款。
提交后、执行前崩溃也保留扣减，这是保守预留，不代表工具已经产生效果。

同一身份重新打开时保留已用额度与原截止时间；重复调用标识、策略变更、额度耗尽、观察到的
时钟回退和 `finish` 关闭状态会持久化，不能重新 `begin` 清零。`finish` 的可选第二参数仅接受
固定的预算停止原因，用于保存进程内单调时钟触发的关闭；它不证明远端任务已停止。新调用必须先 `begin`，不会
懒创建任务。并发写锁冲突或存储异常拒绝本次准入，并关闭当前连接的后续准入；重新打开连接
仍读取原账本。不要通过捕获错误回退到无限制模式。

时间使用跨进程可比较的系统墙钟，停机时间计入截止时间。它依赖可信系统时间，只能检测低于
已记录时间的回退；不能识别所有时钟调整，也不能防御数据库回滚或删除后由管理员重新初始化。
调用方仍需叠加进程内单调时钟限制，并为无工具调用的模型思考阶段安排定时取消。

最多保留 10000 个任务，每个任务最多 10000 次预留；满库拒绝新身份，旧身份不被淘汰。
不提供自动清理、预算迁移或在线重置。仅支持可信本地文件系统上的单个账本，不用于网络共享盘。
不要在活动任务期间替换数据库或恢复旧备份；改变原生任务身份也不会自动继承旧任务的额度。

离线测试覆盖重新打开、截止时间、策略冲突、重复身份、锁冲突、失败写入回滚、跨进程抢占，
以及提交前后杀死真实子进程。测试不调用模型或平台；本账本不能保证远端副作用恰好一次。
